---
name: research
description: Investigate a question against high-trust primary sources and capture the findings as a Markdown file in the repo. Use when the user wants a topic researched, or docs or API facts gathered.
---

Do the reading yourself, in this session, and leave the findings behind as a file — the point of this skill is the discipline about *sources*, not who does the reading.

1. Investigate the question against **primary sources** — official docs, source code, specs, first-party APIs — not a secondary write-up of them. Follow every claim back to the source that owns it. When a package is installed locally, its own source is a primary source and beats any blog about it.
2. Write the findings to a single Markdown file, citing each claim's source.
3. Save it where the repo already keeps such notes; match the existing convention, and if there is none, put it somewhere sensible and say where.
4. Say plainly what you could **not** establish. A gap named is worth more than a plausible guess laundered into a finding.
